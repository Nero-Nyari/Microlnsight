## 第 2 页：项目背景

### 为什么选择 Windows 终端安全？

- **目标**：构建场景化安全智能体，解决实际安全痛点
- **Windows 终端**：90% 企业使用 Windows，安全日志丰富但分析困难
- **AI 赋能**：大模型 + 智能体技术成熟，可实现自动化安全运营
- **痛点**：传统 SIEM 规则死板，告警多、误报高、处置慢

### 参考原型：Windows 10 安全中心
- 病毒和威胁防护 → 自动化检测 + 处置
- 我们的目标：AI 驱动的智能化升级

## 第 5 页：RAG 知识增强

### 为什么需要 RAG？

**问题**：大模型可能"胡说" Windows 事件含义

**方案**：
1. 构建垂直知识库
   - Windows 事件 ID 详解（4625/4624/7045/1116...）
   - MITRE ATT&CK 技战术映射
   - 安全处置预案
2. 向量化存储（ChromaDB）
3. 分析时先检索，再推理

**效果**：
- 消除大模型"幻觉"
- 回答准确、可追溯
- 符合商用标准

## 第 6 页：CoT 思维链展示

### AI 如何一步步思考？

```
发现异常：Security 日志出现事件 ID 4625（登录失败）
   ↓
检索知识库：4625 = 账户登录失败
   ↓
关联分析：同一 IP 192.168.1.100 10 分钟内 50 次失败
   ↓
威胁判定：符合"暴力破解"特征（ATT&CK T1110）
   ↓
处置建议：1.封禁 IP  2.禁用账户  3.开启账户锁定
   ↓
等待决策：用户选择【自动执行】或【手动确认】
```

**价值**：
- 可解释的 AI，每个结论都有推理依据
- 安全分析师可审核、可纠正

## 第 7 页：ReAct 自主闭环

### 从发现到处置的完整闭环

```
[观测] 读取日志 → 发现 4625 暴力破解事件
    ↓
[思考] LLM 分析 → 判定高风险，建议封 IP
    ↓
[行动] 决策引擎 → 生成处置方案
    ↓
[观测] 执行反馈 → 防火墙规则已添加
    ↓
[验证] 再次读日志 → 确认攻击已停止
```

**两种模式**：
- **自动模式**：高危事件自动处置（封 IP、隔离文件）
- **手动模式**：AI 建议，用户确认后执行

## 第 10 页：创新点

### 四大创新

1. **终端场景聚焦**
   - 不同于传统网络层安全，聚焦 Windows 终端日志
   - 贴近企业实际安全运营场景

2. **全链路自动化**
   - 日志读取 → AI 分析 → 处置闭环 → 报告生成
   - 全流程无需人工干预

3. **可解释 AI**
   - CoT 思维链让每一步推理透明可见
   - 符合《人工智能安全治理框架》可信 AI 要求

4. **知识增强**
   - 内置安全知识库解决大模型"幻觉"
   - ATT&CK 映射提升专业深度
