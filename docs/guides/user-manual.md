# Microlnsight 使用说明

当前定位：Windows 日志研判原型。安装、环境检查、启动、测试均使用 [README](workbench.md) 中的统一入口。

## 第一次使用

1. 在应用目录运行 `python dev.py check`，确认 Python 和前端环境可用。
2. 运行 `python dev.py start` 或双击 `start.bat`，等待 Ready。
3. 打开 http://127.0.0.1:5173，按 [三分钟演示](demo-walkthrough.md) 依次体验三个场景。
4. 在启动终端按 Q 或 Ctrl+C 停止服务。

## 界面布局

左侧选择日志或告警，右侧在“分析概览、证据与原文、分析报告、更多详情”间切换。演示案例默认收起，展开后选择并载入。窄窗口选中记录后显示分析区，可点击“日志列表”返回。顶部“工具与设置”集中放置本机日志、知识库、记忆库、系统信息、定时调度和模型管理。

## 日志来源

列表顶部提供“实际日志”和“演示数据”两个独立视图，默认显示实际日志。实际日志包括本机采集和未标记为演示的手动/外部导入；这不是对原文真实性的认证。载入案例后自动进入演示视图，导入实际日志后自动切回。列表数量、日志/告警分类和筛选均限定在当前来源内；切换来源会清空旧详情。列表来源标签和详情顶部提示区会持续标明合成演示记录。历史记录中的 IsDemo、嵌套原文演示标记及演示来源也参与识别，无需迁移数据。

## 导入与分析

“Windows 演示案例”使用明确标注的合成输入。前三个案例按正常运维、单次失败、连续失败后成功组织。第三个案例会一次保存 6 条日志和对应事件。

“导入日志”支持本机读取和粘贴 Windows 文本、JSON、XML。先预览选中的记录，再加入日志列表。Security 通道无权限时按通道提示，其余成功读取的记录仍可导入。

选中一条记录后，点击“运行本地联合分析”。默认检查该记录前后各 15 分钟、同主机已导入的日志，可选择 5/15/30/60 分钟。不调用模型，也不会补采尚未导入的记录。只更新当前选中事件的分析结果。

需要模型解释单条日志时，先在模型管理中确认服务，再显式点击“单条模型分析”。输入将发往当前配置的服务；模拟模式输出不能用作真实检测效果证明。

## 模型管理

模型管理位于“工具与设置 → 模型管理”，与其他工具共用同一个窗口。先查看已配置模型，需要新增时点击“添加模型”；连接测试、设为当前和删除确认均在列表内完成。连接测试会发送简短请求；普通打开页面不调用模型。模型 ID 可输入服务商提供的值，输入框中的候选仅为快捷填写。

## 阅读结果

- **日志列表**：待分析、正常、待核实及分析失败/中断的记录。
- **告警列表**：有原文或独立记录支持的异常线索，仍需人工复核。
- **发现了什么**：当前研判及理由。原始等级和分析后风险分开展示。
- **依据是什么**：时间窗口、失败计数、日志引用、时间线和逐条原文。
- **建议做什么**：核查方向与待补充证据。时间相邻不证明因果关系。
- **报告**：复用当前结论，支持 Markdown 下载，缺失字段显示“未提供”。

重新分析会切换当前显示的分析轮次；历史日志与分析保留。历史报告可能按一致性视图整理展示，以页面提示为准。

## 边界

本地规则未命中并不代表主机安全。Security 读取失败、日志未导入、字段缺失都会限制结论。模型输出需要人工复核。当前演示和验收不包含真实封禁、删除、隔离等处置，也未验证生产部署能力。

数据库、模型配置和真实日志属于本地运行数据，不提交 Git。使用合成案例即可演示，无需上传真实日志到模型服务。
