# Microlnsight 0.3.0 名称迁移

此文说明 0.3.0 的迁移机制。2026-10-13 已完成本地源码目录更名及网页数据库迁移，安装包尚未发布。其他机器上的已有部署仍需按下文步骤迁移。

## 新命名与过渡入口

| 项目 | 新名称或行为 | 旧版本处理 |
| --- | --- | --- |
| 项目、网页、终端和 API | `Microlnsight` | 已统一显示名称 |
| 安装包及解压目录 | `microlnsight-windows-cli.zip`、`microlnsight-linux-cli.tar.gz` | 同时提供旧名称过渡包供旧更新器识别 |
| 数据目录环境变量 | `MICROLNSIGHT_DATA_DIR` | 兼容 `WINSEC_DATA_DIR`，新变量优先 |
| 更新令牌环境变量 | `MICROLNSIGHT_UPDATE_TOKEN` | 兼容 `WINSEC_UPDATE_TOKEN`，新变量优先；新变量为空时禁用旧令牌 |
| 测试环境变量 | `MICROLNSIGHT_TEST_MODE` | 兼容旧变量，新变量优先 |
| 网页默认数据库 | `microlnsight.db` | 旧库存在时提示迁移，拒绝静默创建空库 |
| 知识库集合 | `microlnsight_knowledge` | 停机后原地更名，保留文档和向量 |
| 新建防火墙规则前缀 | `Microlnsight_Block_` | 更新不修改或删除已有系统规则 |
| 源码子目录 | 已更名为 `Microlnsight/` | 工作流和文档路径同步更新；旧检出可使用下文脚本 |

CLI 的任务、模型设置和日志原本位于 `data/agent.guard/`，无旧品牌名称，无需改名。原地升级继续使用原安装目录，不自动移动用户自选路径、快捷方式或虚拟环境。

## 已安装 CLI 的升级

0.2.x 更新器固定查找旧名称文件，因此 0.3.0 默认构建四个压缩包：两种平台的新名称包和旧名称过渡包。过渡包只保留旧的压缩包名称及顶层目录，内含相同的 Microlnsight 程序和新更新器。两个平台的所有包都列入发布校验清单。

旧更新器安装过渡包后，新更新器优先选择 Microlnsight 包；同时兼容旧发布包的解包格式。更新保留任务、模型配置、`.env` 和安装位置，继续执行文件校验、隔离启动自检和失败回滚。过渡包仍需保留，直至不再支持直接从旧版升级。

新安装请下载 Microlnsight 包。已有安装若还要调整磁盘上的安装文件夹名称，应先停止全部进程并备份数据，再移动目录、重新运行安装脚本和更新快捷方式；更新器不会替用户改动任意安装路径。

## 网页数据库迁移

停止旧网页后端、数据库工作台以及其他读写旧库的程序。在包含 `migrate_branding.py` 的应用目录运行：

```powershell
python migrate_branding.py
# 指定其他数据目录时
python migrate_branding.py --database-dir "D:\path\to\data"
```

脚本通过 SQLite 备份接口复制已提交内容，包括 WAL 中的数据，检查完整性后启用新文件；迁移期间阻止其他写事务。原 `winsecagent.db` 保留为回退备份，不删除、不覆盖。目标库已存在、旧库正在写入或校验失败时停止，避免覆盖数据或重复迁移。

迁移后不要重新启动旧服务写入旧库。如果显式设置了 `DATABASE_URL`，仍以用户配置为准；请将该配置指向新文件。原库备份不会跟随新库的后续写入，回退时需要评估迁移后新增数据。

此脚本不接触 CLI 的 `tasks.db`，也不会重写历史报告。本机真实数据库已迁移，内容核对结果见文末。

## 知识库和已有系统规则

使用与原知识库兼容的 Chroma 环境，停止服务并备份知识库目录后运行：

```powershell
python migrate_branding.py --knowledge-dir "D:\path\to\knowledge_db"
```

此选项只更名已有集合，不迁移 SQLite。新旧集合同时存在时拒绝自动合并；原集合不存在时不创建替代集合。依赖不兼容时先恢复原 Chroma 环境，不能将依赖升级与数据更名混为一次操作。

程序今后创建的规则使用新前缀；已有真实防火墙规则不因品牌迁移自动删除或重建，以免改变防护状态。历史系统对象和回退备份中的旧名称属于保留记录。

## 旧检出的源码目录迁移

在仓库根目录执行。先预览：

```powershell
.\scripts\rename-source.ps1
```

关闭使用应用目录的服务、终端及编辑会话后执行：

```powershell
.\scripts\rename-source.ps1 -Apply
```

脚本将 `WinSecAgent/` 更名为 `Microlnsight/`，同步更新 CI、发布流程、忽略规则及当前文档引用，并在 `outputs/source-rename-*/` 备份引用文件。检测到目标已存在时拒绝覆盖；目录仍被占用时停止，不强行结束进程。出现写入错误时尝试恢复原引用和目录，备份保留供核对。

这一步移动源码子目录，不更名包含 `.git` 的整个检出目录。仓库最外层本地文件夹名由使用者决定，不影响项目名称。虚拟环境的启动器可能包含旧绝对路径，移动后按安装说明重新创建环境，避免直接沿用旧启动器。

迁移后检查 `git status --short`，确保新目录源码已纳入提交，运行 Python 测试、前端构建及发行包检查后，再发布新版本。
