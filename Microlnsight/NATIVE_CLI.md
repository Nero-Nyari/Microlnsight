# Microlnsight 本机 CLI 版

从 0.3.0 起，新安装使用 `microlnsight-*-cli` 发行包和目录。发布时额外提供 `winsecagent-*-cli` 过渡包，供旧更新器安装相同的新版本；新更新器优先选择 Microlnsight 包。原地更新保留用户选定的安装目录与本机数据。

环境变量改为 `MICROLNSIGHT_DATA_DIR`、`MICROLNSIGHT_UPDATE_TOKEN`。旧的 `WINSEC_DATA_DIR`、`WINSEC_UPDATE_TOKEN` 仍可用于升级过渡；同时配置时以新变量为准。

## 部署方式

Windows 版装在 Windows 主机，Linux 版装在 Linux 主机。每个实例独立采集和分析本机日志，任务与对话默认保存在安装目录的 `data/agent.guard/`。主机之间无需连接，也不会自动汇总日志。Xshell 可用于登录 Linux 并运行安装命令；关闭终端会结束前台程序。

这两个包是 **Python 源码发行包**，需要 Python 3.10+，没有捆绑 Python 或模型权重。安装脚本创建 `.venv-cli`，只安装本平台 CLI 依赖，不安装网页、向量库和模型运行时。首次安装需要从配置的 Python 包源下载依赖。

## Windows

解压 `microlnsight-windows-cli.zip`，在解压目录执行：

```powershell
.\install-windows.bat
.\start-windows.bat
# 合成演示，无需日志读取权限
.\start-windows.bat demo
# 读取本机 Security 日志
.\start-windows.bat scan
```

安装只需执行一次。Security 读取失败时请使用有事件日志读取权限的终端，例如管理员 PowerShell；程序不会自行提权。

## Linux

把 `microlnsight-linux-cli.tar.gz` 上传到需要保护的 Linux 主机。Ubuntu/Debian 如果没有 Python/venv，先由管理员安装 `python3`、`python3-venv`；其他发行版用对应包管理器。

```sh
tar -xzf microlnsight-linux-cli.tar.gz
cd microlnsight-linux-cli
sh install-linux.sh
sh start-linux.sh
# 合成演示
sh start-linux.sh demo
# 读取当前服务器的 SSH journal
sh start-linux.sh scan --minutes 15 --limit 1000
# 前台持续轮询；Ctrl+C 停止
sh start-linux.sh watch --minutes 15 --interval 60
```

采集依赖本机 `journalctl` 和 SSH 服务 journal。使用有 journal 读取权限的账号；root 可在服务器终端运行。程序不自动 sudo，不调整 SSH 或防火墙配置。不使用 systemd/journal 的系统暂不支持此实时入口；菜单可分析兼容的 `ssh.journal.log` 导出目录。watch 尚未安装为 systemd 服务，读取失败会保存失败任务并退出。

## 统一操作

### 0.3.3 Linux 启动、SSH 会话活动与排除原文

Linux 启动脚本优先使用安装目录的 `.venv-cli/bin/python`；其不可用时尝试系统 `python3` 和版本化的 Python 3.10–3.14，验证 Python 3.10+ 后再进入启动器。启动器继续处理运行锁、更新恢复和 `runtime.json`，不修改系统 Python。没有兼容解释器时给出安装提示。旧启动脚本尚未升级时，可在安装目录执行 `./.venv-cli/bin/python -X utf8 launch_cli.py`。

新任务识别 SSH 建立连接、PAM 会话打开/关闭、子进程创建、终端开始/结束、连接断开和传输统计。首页分别显示登录认证与会话活动数量。会话活动只作上下文，不计入成功/失败认证次数或封禁规则，不证明授权或安全；未知账户/IP 保持为空，不自动关联为某个用户的会话。仅有会话活动时，当前登录规则明确显示无法判断。离线报告使用相同分类。

任务详情输入 **2** 分页查看登录与活动证据，输入 **4** 查看未识别或无效记录的原文、排除原因及保存范围，输入 **3** 导出完整 JSON。每页最多显示 100 条。Linux 新采集及 SSH 导入任务最多保存 1000 条排除记录、原文合计 1 MiB、单条 4096 UTF-8 字节；显示未保存数量和截断数量，截断条目附完整原文的 SHA-256。此上限仅限制保存的排除原文，不改变排除统计。原文留在本机任务中，不自动加入模型请求。

历史任务不改写；旧任务没有保存的排除原文无法补回，需要在系统日志仍可用时重新采集。识别覆盖不等于安全检测覆盖，结论仍仅限本次 SSH 日志和现有规则。

### 全屏工作台

交互终端启动 `python agent.py`（或本平台启动脚本）会进入深色全屏工作台。首页显示开始入口和最近任务的时间、来源与分析结论；时间按运行终端所在主机的本地时区显示。打开任务后，主区域显示分析结果与对话，底部输入提示随任务和模型配置状态变化。宽屏右侧显示当前模型、任务和操作入口；少于 120 列或 26 行时自动隐藏侧栏，小窗口使用精简首页。数据目录等完整信息通过 `/workspace` 查看。`--plain` 可切回普通文本菜单。重定向输出、`TERM=dumb` 或缺少界面依赖时继续使用文本模式；已有安装可重新运行本平台安装脚本以安装新增的 `prompt-toolkit` 依赖。

- 输入 `/demo` 体验演示，`/scan` 启动采集向导，`/tasks` 选择历史任务。
- 输入 `/models` 配置模型，`/parameters` 修改模型参数。密钥输入隐藏，不写入界面对话记录。
- 选定任务后可直接输入问题。非本机模型仍逐次展示发送范围并要求授权；没有授权不会发送。
- `/details` 查看当前任务、证据及导出，`/status` 查看本地模型诊断。
- `/home` 返回首页并保留当前任务，`/workspace` 查看工作区详情、完整模型名称与数据目录。过长的侧栏标签会截短显示。
- `/check-update` 检查更新，`/update` 确认后更新并退出；`/help` 查看所有命令。数字 0–6 仍兼容原菜单。
- Enter 提交，Alt+Enter 换行，Tab 补全命令，PgUp/PgDn 滚动结果，F1 帮助，Ctrl+L 清屏，Ctrl+Q 退出。
- 结果区支持鼠标滚轮、拖动右侧滚动条，翻页按自动换行后的屏幕行移动。上翻阅读期间新输出不会拉回底部；下翻到底部后恢复自动跟随。
- 菜单等待输入时也可输入 `/home`、`/tasks` 等完整命令，结束当前菜单后执行；密钥输入仍按密钥处理。取消采集前的选项不会更换当前任务，创建任务后立即同步侧栏。
- 等待输入时不显示处理耗时；再次提交后重新计时。侧栏依据当前任务的实际采集阶段显示读取状态，不把范围不足直接解释为权限不足。
- Ctrl+C 清空输入或取消当前向导；正在进行的同步采集或网络请求会等待其返回或超时，再返回工作台。请求进行中退出也会先等待，以保留任务写入完整性。

### 普通文本菜单

首页按“分析与核查”“模型与维护”分组，保留原有菜单编号。结果页分为处理阶段、分析结论与范围、异常线索和防护建议；状态同时使用文字标签和颜色。标题、消息和菜单按终端宽度换行。

交互式采集、获取模型列表和等待模型回答时显示等待动画及已用时间；不显示估算百分比。完成或中断后清理等待行并记录耗时。重定向输出和 `TERM=dumb` 使用静态消息；设置 `NO_COLOR` 可关闭颜色。

菜单：1 本机日志分析与防护建议；2 任务、证据与模型追问；3 模型配置；4 本平台合成演示。Windows 支持 Security 4624/4625 登录，以及 5379 凭据读取、4672 特权分配、4627 组成员快照、4798/4799 组枚举、5058/5061 密钥与加密操作；Linux 读取本机 SSH journal。Windows 的 `--limit` 是总条数预算：约一半留给登录，剩余额度均分给其他 7 类，各类先筛选再取最近记录，避免 5379 淹没其他证据。空闲额度不转移，因此可能少于总上限；详情保存各类额度与读取数。很小的额度可能漏查类别，会明确提示。

新增审计事件按类别展示数量、含义、返回码和证据，并保留主体与目标账户、会话、进程及操作字段。4672 特权分配单独出现仅作为活动记录；只有唯一关联的 4624 登录同时命中连续失败后成功规则，且非内置系统服务账户获得敏感特权时，才生成复合核查线索，并引用完整关联依据。账户名、管理员组或登录类型不能证明授权；关联信息缺失也不直接视为异常。临时/下载/公共目录进程枚举组、密钥或加密操作非零返回码仍提示核查；合法操作可能命中，不能当作已确认攻击。这些审计线索不生成 IP 封禁建议。4672/4627 仅在同主机、会话、账户标识且相差不超过 5 秒、匹配唯一时关联 4624。缺少审计细节仍保留事件并报告判断限制。未列出的 Security 事件仍不在本入口范围内。

模型输入区分全部保留记录的本地规则统计与有限证据片段，提供每类的总数、样本数、遗漏数和授权未验证标记。回答附带本地生成的证据范围说明。禁止由样本或“未命中规则”推断其余活动正常；对已识别的泛化正常结论和未提供的证据编号，本地检查会拒绝采用回答，保留诊断并允许重新提问，不自动重试或发送更多日志。该检查不是完整的语义验证，模型回答仍需按引用核实。新规则用于新任务，旧任务的历史结论不会被改写。

Windows 服务登录等事件的来源 IP 可能为 `-`。只要目标账户、主机、时间和记录编号有效，事件就保留为证据并记录登录类型；缺少或无效的 IP 不会被补成回环地址，也不参与按来源 IP 关联的重复失败规则或封禁建议。数据范围分别显示保留记录数与可按来源 IP 关联的记录数。新任务保存事件 ID 分布、缺失字段分项和 IP 可用性统计，供详情、JSON 导出和模型解释共用。旧任务中已排除的原文无法从统计还原，需要重新采集；不会静默改写旧任务。

从 0.2.2 开始，配置与采集向导支持 **回车采用默认值、0 或 Ctrl+C 取消当前操作**。填错地址、目录或保护名单时，只重填当前一项。任务历史按列表序号选择；打开任务后可连续查看证据、追问和导出，无需复制任务 ID。Linux 交互终端启用行编辑，兼容 Xshell 常见的两种退格键编码。

模型配置流程：选择 **本地 Ollama / DeepSeek API / 其他 OpenAI 兼容服务** → 服务地址 → 密钥方式 → 获取模型列表并按序号选择（也可手动填写）→ 显示名称 → 确认保存。DeepSeek 地址默认 `https://api.deepseek.com`。显示名称只是本机标签，不能填写网址。获取列表仅请求模型服务的 `/api/tags` 或 `/models`，不发送日志，也不代表已验证模型能完成推理。服务不可达时可重试或手动填写模型名称。配置过程中取消不会覆盖原配置。

密钥默认隐藏输入，仅当前进程有效；重启后提问时可重新输入，也可选环境变量方式。请在同一次交互菜单中完成配置和提问。获取模型列表的服务端说明见 [DeepSeek 文档](https://api-docs.deepseek.com/api/list-models/)。

启动脚本可以追加 `models`、`tasks`、`tasks 任务ID`、`ask 任务ID`、`scan`、`watch` 或 `demo`。指定数据位置使用 `--data-dir /path/to/data`（Windows 也支持目录路径），该选项放在子命令前；也可设置 `MICROLNSIGHT_DATA_DIR`。

默认不调用模型；在菜单明确启用，或执行 `scan --with-model`。本机模型地址是**当前安装机器**的 localhost。Linux 可配置 Linux 本机 Ollama，Windows 可配置 Windows 本机 Ollama；也支持兼容接口和 API。非本机地址须逐次确认；非交互命令还需 `--allow-remote-model`，才发送有限证据摘要。API Key 可隐藏输入，仅存当前交互进程，或通过环境变量读取。程序不捆绑本地模型，无模型服务时仍可运行规则分析。

### 分析覆盖明细

当前源码中的分析覆盖明细区分采集上限、采集警告、消息暂不支持、必要字段缺失或无效、来源无法确认、格式无效与记录冲突。详情显示读取、参与分析、排除、重复合并和冲突的数量；首页和侧栏显示具体限制原因，完整原因见 `/details`。达到上限表示可能未读全，未读数量未知；排除记录不代表权限不足，也不代表没有安全价值。

新采集任务保存排除类别及采集参数；历史任务若只有排除总数，会显示“排除原因未细分”，不推测类别、不改写历史数据。已有固定的采集上限警告可用于显示“达到采集上限”。完整 JSON 导出的 `analysis_scope` 与模型收到的同名字段使用相同覆盖说明；结论仅适用于已分析记录，参与分析的比例不代表检测准确率。

### 0.2.6 分析结论与终端体验

首页菜单分组，结果页分区显示处理阶段、结论、线索和防护建议。等待采集和模型回答时显示耗时；窄终端自动换行，重定向输出使用静态消息。

结论明确区分“数据不足，无法判断”“在已分析范围内未发现规则线索”和“发现待核查线索”，并单独说明分析范围不完整。任务详情与模型证据摘要使用相同结论。Linux 本机与离线 SSH 日志共用来源校验，排除非 SSH 进程消息及缺少必要字段的记录。

继续仅提供防护建议，不执行真实封禁。保留现有数据、模型配置和历史回答。

### 0.2.5 防护建议用语

菜单、任务和结果页统一使用“防护建议”，每条建议明确标注“尚未执行；未修改服务器防火墙”。真实日志和合成演示数据仍分别标识。保护名单内的地址明确显示“不建议封禁”。新模型回答也使用建议口吻。

已有任务使用新界面展示；历史模型回答保持原文。数据库和完整 JSON 导出保留原有模拟状态及内部自检字段，保持审计兼容；这些字段不代表实际执行或封禁成功。

### 0.2.4 终端回答排版

模型解释、新的追问回答和历史对话均保留段落：标题单独显示，列表按项缩进，Markdown 表格转换为逐行字段，代码块保留原始换行和缩进。长命令按终端宽度显示，`↪` 只是视觉续行标记；需要复制命令时请使用任务导出的原文，避免把显示标记一起复制。原始模型回答仍完整保存在任务或对话中，不改写证据与导出内容，也不会执行回答中的代码。

新回答会被要求采用“简短结论、证据、未知项、下一步核查”的段落结构。已有任务直接打开即可使用新排版，无需重新调用模型。

### 0.2.3 模型回答与诊断

旧 DeepSeek 官方接口配置在读取时自动采用新默认值：关闭思考模式、输出上限 4096 tokens、连接后读取等待上限 180 秒，无需删除重建配置。仅对 `api.deepseek.com` 应用 DeepSeek 专用参数；其他 OpenAI 兼容服务与 Ollama 保留服务默认思考行为。

菜单 **3 模型配置 → 3 调整当前模型参数** 可选择 DeepSeek 普通回答/深度思考、输出额度（256–65536 tokens）与读取等待时间（10–600 秒）。从普通回答切到深度思考时建议额度为 16384，可修改；提高额度可能增加耗时与费用。模型服务仍可能拒绝超过自身限制的值。读取等待时间不是整个请求的绝对总时长。配置参数不会发送推理请求。

接口适配依据 [DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)：明确处理 `finish_reason`，输出达到上限时不把部分答案当完整报告，也不把 `reasoning_content` 当最终答案。错误区分 HTTP 状态、网络/超时、无效 JSON、结构不兼容、输出截断、仅有思考及空答案。不自动重试或切换模型。

失败后只保存固定错误类别、结束原因、是否有思考内容、答案字符数及服务返回的数值用量；不保存响应正文、思考正文、认证头或密钥。诊断随任务保存在本机，可在追问中输入 `/status` 查看，不发送请求；下一次经授权的提问会包含诊断，便于解释失败原因。成功后更新最新提问状态，原始自动分析结果仍保留。

远端模型可输入 `y` 仅授权当前问题，或 `s` 授权当前任务的本次对话及后续问题。退出追问或切换模型配置后需重新确认。无登录证据时明确提示只能咨询排查方法；Linux 本机采集向导可设置最近 1–1440 分钟的范围，不会把未识别记录当成有效登录证据。

目前仅提供**防护建议，尚未执行**：不改动实际防火墙，防护效果尚未验证。内部仍保留规则创建、到期失效和撤销的内存测试，供开发验证；不在建议页面展示成防护结果。重复失败线索不等于确认入侵成功。

旧入口 `python dev.py cli` 及原 Windows 数据库功能保留在源码工程中。本机发行包聚焦跨平台登录防护流程，不包含网页和完整 Windows 历史数据库工作台，不迁移旧开发数据。

## 历史报告分析（0.3.4）

全屏工作台输入 `/reports`，普通菜单选择 **7 历史报告分析与本地模型**；也可从 `/scan` 选择来源 **4 历史 SSH 归档**。命令行直接运行 `bash start-linux.sh reports`（Windows 为 `start-windows.bat reports`）。

1. 选择 **新建历史分析**，选择服务器归档。安装目录同级 `collector/raw` 会自动出现，来源名称取自采集器配置；也可添加其他已有的 `raw/*.jsonl` 目录。本入口读取本机归档，不连接公网服务器重新采集。
2. 输入时区、开始和结束时间。格式为 `YYYY-MM-DD HH:MM`，结束时间包含整分钟，例如 `2026-10-16 16:35` 包含到 16:35:59；时区默认取运行机器，必须核对。
3. 检查实际起止时间、日志条数、批次数、去重与无效记录。准备快照不会调用模型。点击开始前显示实际 Ollama 地址、模型和发送范围；只分析所选范围内已归档的完整消息，不采用任务追问的 30 条证据上限。
4. 选择开始，逐批保存模型回答。Ctrl+C 会在当前请求结束后停止；再次进入 **查看报告 / 续跑** 可继续，成功批次不会重复发送。已有报告固定使用创建时绑定的模型，不跟随当前模型配置切换。
5. 查看分批报告时，`n/p` 翻批，`e` 看原文，`a` 针对当前批次向同一本地模型提问，`h` 看已保存追问。追问只发送当前批次的完整证据和本次问题，不发送其他批次或历史对话；每次会显示并确认范围。完整报告可导出为 Markdown。

新报告保存在数据目录的 `history-analysis/`。过去脚本生成的、位于安装目录同级 `history-analysis/` 的报告也会出现在列表中。原始归档和定时采集不变；历史报告独立保存，不混入滚动 20 分钟的 `/tasks` 列表。

0.3.5 起，每条观察和待核实线索旁显示“引用日志时间”，按引用编号从原始证据读取，保留日期、时区和原有时间精度；多条引用显示最早至最晚时间。这是所引证据的范围，不表示整个事件的持续时间。历史报告和已保存追问也会显示；重新导出旧报告即可取得带时间的 Markdown，无需再调用模型。

分批模型采用 Ollama、8192 上下文、2048 输出额度、关闭思考；这些固定参数独立于普通任务的 `/parameters`。每批最多两次尝试，覆盖编号或长度失败时拆成两小批，各最多两次；所有尝试留档。检查通过仅说明返回格式与证据编号符合要求，不能保证推理正确。全量指所选时间段中实际保存的归档，不代表全天连续采集或完整主机审计。

## 发行包检查

包内 `SHA256SUMS.txt` 校验源文件，包外清单校验压缩包。打包采用固定清单，排除开发数据库、真实日志、虚拟环境、`.env` 和模型密钥。

## 检查和更新已安装版本

本机工作台菜单 **5 检查更新、6 更新并退出**。只检查不会安装，不会上传日志。更新成功后重新执行启动脚本。

Windows：

```powershell
.\start-windows.bat version
.\start-windows.bat check-update
.\start-windows.bat update
```

Linux：

```sh
sh start-linux.sh version
sh start-linux.sh check-update
sh start-linux.sh update
```

`update --yes` 可用于明确授权的非交互更新。请先停止同一安装目录的 watch/其他实例；运行锁会阻止并发更新。安装目录需要当前账号有写权限，程序不会自动提权。

更新源固定为 `Nero-Nyari/Microlnsight` 的 GitHub Releases，检查最近 30 个发布条目中的 `cli-vX.Y.Z` 稳定版本，比较数字版本号。源码分支的普通提交不会直接安装，草稿和预发布也不会安装。更新按 [GitHub Releases 接口](https://docs.github.com/en/rest/releases/releases) 读取元数据。仓库未发布、网络错误和没有更新分别提示。

私有仓库需要在当前机器设置 `MICROLNSIGHT_UPDATE_TOKEN` 环境变量，令牌仅需该仓库 Contents 读取权限。不要将令牌放进启动脚本、聊天、Git 或模型配置。更新器只向 `api.github.com` 发送此令牌；下载跳转到其他主机时移除认证头。未授权或地址不可访问会报错，不会被当成“已是最新版”。

下载后校验整包 SHA256、包内各文件哈希、平台和版本。只替换程序清单中的文件，保留 `data/`、`.env`、模型配置及本机额外文件。如果已有程序文件被手动修改，停止更新并指出冲突，避免覆盖你的修改。自定义日志/数据应放在 `data/` 或安装目录之外。

依赖未变时沿用当前环境；有变化时在 `.updates/env-*` 创建独立环境并安装，原环境保留。隔离演示试运行成功后才切换程序和 `runtime.json` 环境指针。新版的模拟自检不会读取真实日志或调用模型。替换失败会恢复旧文件；替换过程中被中断，下次从启动脚本启动时读取事务记录恢复旧版。旧文件备份留在 `.updates/事务ID/backup`，此目录与旧环境暂不自动清理。

第一次使用更新功能需要安装包含本节功能的新包。此前没有更新器的样板包需要手动替换一次程序文件，保留 `data/`。之后使用更新菜单即可。开发源码目录不会自我覆盖，应通过 Git 管理更新。

### 维护者发布新版本

先提交代码、测试和 `.github/workflows/cli-release.yml` 到仓库，再为通过审核的提交创建递增的版本标签，例如下一版 `cli-v0.2.6`，推送该标签。发布工作流在 Windows/Ubuntu 上验证解析、本机发行包和更新事务；通过后构建两个包及校验清单并创建 GitHub Release。已安装的客户端随后能检查到它。只在本机修改或打包不会产生可下载的线上更新。

本地打包：`python build_cli_releases.py --version 0.2.6`。包内版本写入 `edition.json`，不要修改已发布标签下的资产内容；后续变更发布更高版本。更新流程保留本机数据，但未来涉及数据库格式变更的版本仍需单独实现并验证迁移，本样板尚无数据格式迁移机制。
